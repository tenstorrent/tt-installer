# tt-installer(1)

## Name

`tt-installer` - install the Tenstorrent software stack

## Synopsis

```bash
./install.sh [options]
```

## Description

`tt-installer` installs the Tenstorrent software stack on supported Debian-
based and RPM-based Linux systems.

It detects the host distribution, selects the package manager, resolves
component versions, and configures the selected Tenstorrent tools.

## Options

The full option list is generated by Argbash and is available via:

```bash
./install.sh --help
```

Options commonly used with dry-run:

- `--dry-run`
- `--versions=release`
- `--versions=rolling`
- `--versions=/path/to/state.ttis`
- `--mode-container`
- `--install-container-runtime=auto|docker|podman|none`
- `--update-firmware=on|off|force`

## Dry run

`--dry-run` prints the resolved installation plan without changing the host.

The preview includes:

- detected distribution and version
- host architecture and kernel version
- system packages and Python packages selected for installation
- HugePages state that would be applied
- selected container runtime
- container images and whether each pull is immediate, deferred, or disabled
- firmware version and firmware action
- privileged operations that are suppressed during preview

Dry-run may fetch read-only release metadata or a release channel state file.
It does not download installation payloads. The result is a preview, not a
simulation: package availability, network responses, and runtime behavior may
change before the real installation runs.

The preview uses the same channel tools as a normal install. `jq` is required
for the `release` channel and imported `.ttis` files. `curl` is required for
release and rolling metadata lookups.

## Exit status

- `0` when the plan can be built successfully
- non-zero for invalid arguments or invalid `.ttis` files

## Files

- `install.m4` - source template for the generated installer
- `install.sh` - generated installer
- `ttis.sh` - schema validation and import/export helpers
- `tests/test-dry-run.sh` - black-box dry-run contract tests
- `tests/unit/test-planning.sh` - unit tests for planning helpers
- `tests/test-generation.sh` - generation/inlining checks
- `tests/run-docker-matrix.sh` - local multi-distro Docker smoke test

## Compatibility

The current implementation is validated locally on x86_64/amd64 systems.
The default container images and the documented workflows target amd64.

This is an upstream shell installer, not a Debian or RPM package. The dry-run
path follows the parts of the distribution guidance that apply here:

- no new external dependency added for the dry-run path
- no system writes during preview mode
- deterministic output for preview/testing
- explicit failure for invalid arguments and invalid `.ttis` files
- documentation stored with the source

## Distribution guidance

Debian, Ubuntu, Fedora, and RHEL packaging rules are guidance for this work,
not a claim that `tt-installer` is a native distro package. The implementation
uses clear exit codes, deterministic plan output, documented architecture
limits, and a reproducible generated installer.

## Validation

Locally verified with:

```bash
make test
make test-static
make test-docker
```

The checks also cover:

- `bash -n` on the test scripts
- `shellcheck` on the test scripts
- `shellcheck -x install.m4` after line-ending normalization
- local Docker matrix across Ubuntu, Debian, and Fedora containers

## Examples

Preview an imported state file:

```bash
./install.sh --dry-run --versions=/path/to/state.ttis
```

Preview a hardware-free install:

```bash
./install.sh --dry-run --mode-container
```
